# マルチユーザーバッチ管理システム

**作成日**: 2026-01-11
**対象ファイル**: `Code.js`

---

## 1. 概要

複数ユーザーが同じスプレッドシートを共有して、それぞれの求人データをインポートできるようにするシステム。各インポートにバッチIDを付与し、データの共存とアーカイブを管理。

## 2. 課題と解決策

### 2.1 以前の問題点

| 項目 | 状態 | リスク |
|------|------|--------|
| データ管理 | 上書きモード | 最後のインポートでデータ消失 |
| ユーザー識別 | なし | 誰がインポートしたか不明 |
| データ蓄積 | 無制限 | パフォーマンス低下 |

### 2.2 解決策

1. **バッチ管理**: 各インポートにユニークなバッチIDを付与
2. **追記モード**: データを上書きせず追記
3. **自動アーカイブ**: 1000件超過時に古いバッチを月次シートに移動

## 3. データ構造

### 3.1 データシートのカラム構成

| 列 | 名前 | 説明 | 背景色 |
|----|------|------|--------|
| A | バッチID | 例: `B20260111_183000_tanaka` | 緑 |
| B | 担当者 | ユーザー名（メールの@前） | 緑 |
| C | インポート日時 | `2026-01-11 18:30:00` | 緑 |
| D | 求人タイトル | 求人名 | 赤 |
| E | 求人URL | リンク | 赤 |
| F | 新着 | フラグ | 赤 |
| G | 事業所名 | 会社名 | 赤 |
| H | 所在地 | 住所 | 赤 |
| ... | ... | ... | ... |

### 3.2 バッチID形式

```
B{yyyyMMdd}_{HHmmss}_{userName}
```

例: `B20260111_183045_tanaka`

## 4. 自動アーカイブ

### 4.1 トリガー条件

- データ件数が **1,000件** を超過

### 4.2 アーカイブ処理

```
1. 古いバッチから順に選択
2. 目標: アクティブデータを500件以下に削減
3. バッチ単位で移動（途中分割しない）
4. 月次アーカイブシートに追記
5. 集計キャッシュを更新
```

### 4.3 アーカイブシート命名

```
アーカイブ_{yyyyMM}
```

例: `アーカイブ_202601`

## 5. 使用シナリオ

### シナリオ1: 通常のインポート

```
田中さん（10:00）
├─ CSVインポート: 100件
├─ バッチID: B20260111_100000_tanaka
└─ データシート: 100件

佐藤さん（11:00）
├─ CSVインポート: 150件
├─ バッチID: B20260111_110000_sato
└─ データシート: 250件（追記）
```

### シナリオ2: 自動アーカイブ発動

```
データシート: 1,050件（閾値超過）
├─ アーカイブトリガー発動
├─ 古いバッチ3件（600件）を移動
├─ アーカイブ_202601: 600件
└─ データシート: 450件
```

### シナリオ3: 週次ミーティング

```
分析対象の選択:
├─ 今週のデータのみ → データシートを使用
├─ 全期間データ → アーカイブ集計も含める
└─ 特定担当者 → バッチIDでフィルター
```

## 6. メニュー操作

### 6.1 バッチ管理メニュー

```
データ処理 → 📦 バッチ管理
├─ バッチ一覧を表示
├─ 手動アーカイブ実行
└─ アーカイブ状態を表示
```

### 6.2 バッチ一覧表示

現在のアクティブなバッチを表示:
- バッチID
- 担当者名
- インポート日時
- 件数

### 6.3 手動アーカイブ

閾値に達していなくても手動でアーカイブを実行可能。

### 6.4 アーカイブ状態

- 合計アーカイブ件数
- 月次アーカイブ一覧
- 都道府県別集計（上位5件）
- 雇用形態別集計

## 8. API関数

### 8.1 BatchManager

| 関数 | 説明 |
|------|------|
| `generateBatchId(userName)` | バッチIDを生成 |
| `getBatchList()` | アクティブなバッチ一覧を取得 |
| `getActiveRecordCount()` | アクティブなデータ件数を取得 |
| `needsArchive()` | アーカイブが必要かチェック |
| `executeAutoArchive()` | 自動アーカイブを実行 |
| `getArchiveAggregation()` | 全アーカイブの集計を取得 |
| `deleteBatch(batchId)` | 特定のバッチを削除 |

### 8.2 使用例

```javascript
// バッチ一覧を取得
const batches = BatchManager.getBatchList();
batches.forEach(b => {
  console.log(b.batchId + ': ' + b.recordCount + '件');
});

// アーカイブ集計を取得（全期間分析用）
const archive = BatchManager.getArchiveAggregation();
console.log('アーカイブ合計: ' + archive.totalRecords + '件');
```

## 9. 制限事項

| 項目 | 制限 | 理由 |
|------|------|------|
| アーカイブ閾値 | 1,000件 | パフォーマンスとスプレッドシート制限のバランス |
| バッチ最小単位 | 1バッチ全体 | データ整合性を維持 |
| 集計キャッシュ | PropertiesService | 9KB/キー制限、JSON形式 |

## 11. マイグレーション

### 既存データへの対応

既存のデータシート（A-C列がない場合）は、次回インポート時に新しい形式で追記されます。古いデータとの混在を避けるため、初回は手動で既存データをクリアすることを推奨。

### マイグレーション手順

1. 現在のデータをエクスポート（必要に応じて）
2. データシートをクリア
3. 新規CSVをインポート（新形式で保存される）
